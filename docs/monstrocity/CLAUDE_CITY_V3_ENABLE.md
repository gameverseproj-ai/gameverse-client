# Claude: подключить большой город к реальному серверному забегу Monstrocity

Работай только в be-core. Клиент поддерживает карту city-v3. Визуальный preview клиента не является выполнением этой задачи.

## Обнаруженная причина

29 октября 2026 проверен настоящий GET /api/monstrocity/bootstrap после anonymous auth: config.version=monstrocity-v3, config.mapVersion=courtyard-v1. Поэтому обычный игрок по-прежнему ограничен первым двором 34 × 34 м. Предыдущий экспорт city-v2 не был подключён к backend.

## Что подключить

- Новый mapVersion: **city-v3**.
- Конфигурация **monstrocity-v4** (или следующая свободная; monstrocity-v3 уже занята шестиминутными сутками).
- Геометрия из **city-v3.manifest.json**, правила из **city-v3.rules.json**.
- Границы X/Z: [-77,77]. Размер 154 × 154 м, 23 716 м² — в 20,5156 раза больше исходных 1 156 м².
- 25 кварталов, 96 зданий, 131 контейнер, 30 доступных домов, 26 жителей, 29 кандидатов убежищ.

Используй существующую загрузку versioned resources: maps/city-v3.json + config/<configVersion>.json + config/<configVersion>.balance.json. Подключи новую configVersion в реально запущенном приложении. Не оставляй новый JSON рядом со старой активной конфигурацией, не ограничивайся тестом preview. В конце заново запусти сервер и укажи точную действующую configVersion/mapVersion.

Сохрани утверждённые сутки: day=120, evening=60, night=120, morning=60. Не меняй онлайн/офлайн-расход энергии без отдельного утверждения. Примени согласованный лёгкий профиль первого боя из CLAUDE_COMBAT_TEST_BALANCE.md, если он уже принят, через новую версию.

## Текущий активный забег тоже должен получить расширение

Пользователь продолжает существующий забег: одного изменения карты для следующего старта недостаточно. Добавь безопасную идемпотентную миграцию courtyard-v1 → city-v3 без смерти и без нового забега. Центральный двор, старые IDs контейнеров и первые пять кандидатов убежищ сохранены в исходных координатах. Новая застройка размещена вне старого двора.

Мигрируй атомарно и только вне боя, поиска, диалога и другого незавершённого действия. Сначала сохрани settlement старого состояния. Сохрани player/run ID, дни, activeElapsedMs, энергию, координаты, покупки, найденный инвентарь, searched/spoken IDs, известные убежища, RNG и последовательность input. Установи новую mapVersion и configVersion согласованно, один раз увеличь revision. При повторном bootstrap/resume миграция не повторяется. Если нужно дождаться завершения боя/поиска, миграция автоматически выполняется после него. Не требуй сбросить прогресс или умереть ради новой карты.

Для v1/v2-конфигураций с прежними сутками используй существующий механизм безопасной миграции времени; не пересчитывай накопленные дни простым делением старого elapsed на 360 секунд. Другие неизвестные версии не мигрируй вслепую.

Старые известные и стартовое убежища обязаны оставаться безопасными. Дополнительные активные убежища распределяй по новым районам; неизвестные убежища клиенту заранее не раскрывай. Не делай все кандидаты видимыми. Соблюдай раздельные понятия accessible house и safe shelter.

## Коллизии, находки, NPC

Движение и проверки дистанций — по новому манифесту, без скрытого clamp ±17. Нельзя принимать клиентскую позицию как авторитетную. Только interior=true допускает вход через северную дверь шириной 2 м. Каждый внутренний гарантированный контейнер из rules.guaranteedContainerIds даёт минимум один collectible при первом обыске; повторный ключ/повтор поиска не дублирует награду. Сохрани существующие правила смерти и покупок.

Маршруты и единая формула движения NPC описаны в city-v3.rules.json и CLAUDE_CITY_EXPANSION.md. nearby.position и дистанция talk должны соответствовать фактической позиции жителя. Выбор одежды NPC и графика полностью клиентские.

## Обязательное подтверждение через реальный HTTP

На отдельном тестовом игроке/изолированной БД:
1. Создай старый забег courtyard-v1 с ненулевыми днями, инвентарём и открытым убежищем. После миграции те же значения сохранены, run ID тот же, snapshot.mapVersion=city-v3, закреплённая configVersion соответствует city-v3.
2. Новому игроку bootstrap отдаёт city-v3. Обычный create/resume не возвращает его в courtyard-v1.
3. Пройди sync-командами из старого двора за координаты ±17, затем к северным/южным/восточным/западным внешним районам, включая около |x|/|z|=60–70. Телепортирование БД не заменяет проверку движения через HTTP.
4. В дальнем районе обыщи контейнер, пополни инвентарь, найди убежище. Pause/resume и повторный GET сохраняют дальнюю позицию, обыск и знания.
5. Проверь край ±77 и запрет выхода за него. Проверь доступный вход, закрытые здания и старый центральный двор.
6. Повтори миграцию/транспортный запрос: нет повторной награды, потери прогресса или лишней revision. Отклонённая команда не откатывает уже установленную новую карту.

При сдаче приведи фактический ответ bootstrap (без токенов), snapshot после миграции и результаты этих проверок. Если задача не выполнена на работающем сервере, прямо укажи это — не называй расширение подключённым.
