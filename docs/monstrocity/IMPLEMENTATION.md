# Первый игровой срез Монстросити

Реализован отдельный лениво загружаемый маршрут `/games/monstrocity`, вход с карточки Worlds. Серверный код не изменялся. По умолчанию используется реальный HTTP backend. Результаты проверки и оставшиеся серверные дефекты описаны в INTEGRATION_REPORT.md.

## Можно проверить сейчас

- Выбор персонажа, начало и продолжение забега.
- Настоящий 3D-квартал: фасады, освещение по фазам суток, мостовая, деревья, фонтан, доступное помещение. Геометрия и движения не используют фон концепта.
- Джойстик, WASD/стрелки, независимое смещение камеры справа и мягкий возврат.
- Препятствия, близость контейнеров/жителей, обыск с отменой при движении, еда и вода в инвентаре.
- Карта, отмечаемые убежища, диалоги жителей, пауза в меню; закрытие по Escape, X или тапу снаружи.
- Обнаружение монстром, возможность уйти или скрыться за зданием для необязательной встречи.
- 2D-бой с Мшистиком: прицел, время полёта, попадания, cooldown, последнее окно меча, победа/смерть и возврат в квартал. Камни не коллекционные.
- Дни активного выживания, расход энергии, сохранение состояния, 120 секунд возврата вне убежища, сохраняемый 60-секундный recovery после офлайн-убежища.
- Сброс собранных предметов и знаний об убежищах после смерти; раздельные purchased/collected, расход collected первым. Реальных покупок и рекламы нет.
- Переводы en/ru/he/ar, неизменная геометрия движения и прицела в RTL.

## Архитектура клиента

Исходники: `src/app/features/games/monstrocity/`.

- monstrocity.component: экран, pointer/keyboard ввод, сериализованная очередь запросов, кадры рендера вне Angular, управление паузой и жизненным циклом.
- monstrocity.scene: собственная Three.js-сцена, объединение статической геометрии по материалам, ограниченный DPR с понижением при низкой частоте кадров, очистка GPU-ресурсов.
- monstrocity-local.api: локальная модель для игры до готовности сервера. Ключ хранения `gameverse.monstrocity.preview.v1`; это изменяемые пользователем локальные данные, не источник доверенных результатов.
- monstrocity-http.api: готовые HTTP-запросы по OpenAPI; использует существующий авторизационный interceptor. Включён по умолчанию; сохраняет error snapshots и идемпотентность транспортных повторов.
- monstrocity.types: типы по OpenAPI; monstrocity.config — экспериментальная конфигурация локального режима.
- monstrocity.map / courtyard.manifest.json: общая геометрия и точки взаимодействия для Клода.

Локальный адаптер включается только явно через `?preview=1` в dev-сборке на localhost. Его данные не переносятся в реальный профиль; автоматического fallback при ошибке сервера нет.

## Ограничения первого среза

Это рабочая основа игрового цикла, не финальная художественная реализация. Модели персонажей и города проще утверждённого концепта; нужны дальнейшие авторские модели, анимации и детализация. В локальной версии один готовый тип монстра, один квартал и один интерьер. Вариативность убежищ ограничена подготовленными местами. Обысканные контейнеры не пополняются в текущем забеге. Реальные реклама и покупки не включены. HTTP backend подключён; интеграционные ограничения перечислены в INTEGRATION_REPORT.md.

Физические Android-устройства пока не тестировались. Автоматическая адаптация DPR не является подтверждением производительности на слабых телефонах. Локальная симуляция позволяет быстро проверить поведение, а результаты авторитетных серверных проверок описаны в INTEGRATION_REPORT.md.

`npm run build`

`npm test -- --watch=false --browsers=ChromeHeadless --include=src/app/features/games/monstrocity/monstrocity-local.spec.ts --include=src/app/features/games/monstrocity/monstrocity-http.spec.ts --include=src/app/core/audio/music.service.spec.ts`

Дополнительно проверены 10 сценариев общего MusicService, включая временную передачу звука игре.

Для браузерного smoke-теста запустить приложение на порту 4300 и `node scripts/monstrocity-smoke.cjs` под Node 20+ с Playwright и Chrome. При нестандартной установке задать PLAYWRIGHT_MODULE; MONSTROCITY_URL меняет origin. Тест намеренно отключает остальные API: проверяется изолированная локальная игра, не вход в аккаунт. Сценарий: Worlds → джойстик → обыск → пауза карты → еда → reload/continue → бой и победа → мобильный инвентарь. Снимки пишутся в /tmp/monstro-*.png. Также проверяются реальные позы суставов в dev-сборке Angular, запуск/выключение/возобновление музыки и её остановка при паузе.

## Движение и звук (21 октября 2026)

- Мшистик в слое 2D-боя теперь рендерится как суставная модель в ортографической проекции: отдельные бёдра, колени, плечи, перенос веса и реакция на попадание. Статичный PNG остался только для предупреждения в городе.
- У игрока сглажены переходы между сетевыми позициями, скорость шага зависит от расстояния, добавлены сгибание коленей, мягкий поворот и маркер направления. В бою рука показывает подготовку и бросок, индикатор показывает приближение.
- Собственная синтезируемая тема Monstrocity: перебор клавиш, мягкие аккорды, ночная вариация и пульс боя. Запускается после нажатия «Начать», выключается кнопкой ♪, запоминает выбор на устройстве. Меню и скрытая вкладка приостанавливают звук, выход освобождает AudioContext. Общая музыка приложения временно уступает место теме игры без изменения настроек аккаунта.
- Новые локальные preview-забеги используют monstrocity-v2 с более низкой траекторией цели. Старые v1 продолжаются с прежней траекторией; OpenAPI не менялся, формула уточнена в protocol.md.

## Интеграция с backend

Проверены 36 клиентских тестов, 39 серверных тестов, 65 ответов по схемам и реальный браузерный E2E. Найдены три серверные ошибки; см. INTEGRATION_REPORT.md и CLAUDE_BACKEND_FOLLOWUP.md. Сервер пока выдаёт monstrocity-v1, и HTTP-клиент использует именно эту версию. Для серверного twigwalker добавлена отдельная вариация суставной модели.

## Выбор героя на первом экране

Вместо кнопок пола и старта — общая с городом 3D-модель исследователя на медленно вращающемся постаменте. Свайп в любую горизонтальную сторону переключает пол, двойной тап/клик начинает игру. Один тап, вертикальный жест и удержание не запускают путешествие. Клавиатура: стрелки меняют героя, Enter/Space запускают. Предпочтение уменьшенного движения останавливает автоповорот.

`UserPrefsService` сохраняет `monstrocityAvatar` на устройстве отдельно по playerId; локальный preview использует отдельный namespace. Выбор восстанавливается до создания нового забега. Активный забег продолжает своего существующего персонажа. Серверная синхронизация предпочтения между устройствами пока не реализована — задание в CLAUDE_AVATAR_PREFS.md.

Браузерный регрессионный сценарий: `node scripts/monstrocity-avatar-smoke.cjs` (Playwright/Chrome, dev :4300, explicit preview). Старые smoke/E2E сценарии обновлены на двойной клик по аватару.

Проверка нового экрана: production build PASS, 4/4 UserPrefs tests PASS; Chrome touch/desktop smoke PASS (вращение, оба направления свайпа, клавиатурная смена, восстановление после reload, отсутствие старта по одиночному тапу, старт двойным тапом, продолжение двойным кликом). Скриншоты: output/monstrocity/avatar-landscape.png и avatar-portrait.png. Физический телефон этим тестом не проверялся.
