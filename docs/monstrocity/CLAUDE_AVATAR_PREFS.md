# Клоду: предпочтение аватара Monstrocity

На первом экране клиент убрал две кнопки выбора пола и кнопку старта. Теперь показана медленно вращающаяся модель персонажа: горизонтальный свайп меняет male/female, двойной тап начинает новую игру или продолжает активную. Для активного забега показывается его текущий персонаж; менять персонажа посреди забега нельзя.

Выбор сразу сохраняется клиентом в UserPrefsService: account-scoped localStorage `gameverse.user-prefs.v1.<playerId>`, поле `monstrocityAvatar: male | female`. Это работает до старта забега, после reload и повторного открытия на том же устройстве. Preview хранится отдельно. Для синхронизации между устройствами нужна серверная часть; пока клиент не вызывает несуществующий endpoint.

Добавь в пользовательские предпочтения поле `monstrocityAvatar` и согласованный API чтения/обновления (предпочтительно существующий общий prefs, если он появится). Предлагаемый узкий контракт: GET/PATCH `/api/player/preferences/monstrocity`, JSON `{ "avatar": "male" | "female" }`. PATCH только от аутентифицированного пользователя, проверка enum, не меняет текущий run/profile.character задним числом. Чтение возвращает сохранённое значение или null, если выбора ещё не было; выбор нового забега может служить начальным значением при миграции, но не должен перетирать более позднее предпочтение. После реализации сообщи точный контракт, Codex подключит клиент. Серверный код в этом клиентском изменении не редактировался.
