# Монстросити — дизайн и серверный контракт

Этап 1 выполнен: визуальные концепты, интерактивный макет интерфейса и проект API для параллельной серверной работы. Теперь реализован 3D-клиент с реальным HTTP backend: вход с Worlds → /games/monstrocity. Текущий статус, ограничения и проверки — в IMPLEMENTATION.md. Backend этим пакетом не реализован.

## Смотреть

Откройте preview.html в браузере. Карта, инвентарь, использование припасов, демонстрационный обыск и пауза работают локально. Фон — концепт, джойстик и камера не двигают персонажа. Внизу страницы арт-лист с персонажами и боем. Весь макет отделён от production-приложения.

VISUAL_DIRECTION.md описывает арт, взаимодействия и переход от концептов к игровым ассетам. Исходные промпты встроенного image_gen сохранены рядом с изображениями в ../art/monstrocity.

## Передать Клоду

Отправьте CLAUDE_BACKEND_PROMPT.md вместе с openapi.json, protocol.md, bootstrap.example.json и ../MONSTROCITY_DESIGN.md. Упакованный комплект находится в ../../../output/monstrocity/server-handoff.zip относительно этой папки.

Контракт v0.1 описывает 13 HTTP-операций и 31 схему. Реальные ответы backend проверены по схемам и браузерным E2E; найденные поведенческие ошибки перечислены в INTEGRATION_REPORT.md. Примеры баланса помечены как предложения. Изменения контракта со стороны Клода нужно согласовать с клиентской реализацией.

## Проверка

Из корня репозитория: `node docs/monstrocity/validate-contract.cjs`. Проверяются ссылки схем, компиляция JSON Schema, пример bootstrap, идемпотентные заголовки и отклонение отрицательного количества предметов. Это не полноценная валидация всех правил OpenAPI и не интеграционный тест сервера.

Макет проверен в Chrome: карта, пауза часов, Escape, расход еды/воды с приоритетом collected, однократный обыск и отсутствие горизонтального переполнения при ширине 844 px. Снимки preview-desktop.png и preview-mobile.png находятся в ../art/monstrocity. Это проверка макета, не производительности Android.

## План последующей доработки клиента

Manifest квартала подготовлен в courtyard.manifest.json; далее доработать оригинальные 3D-модели/анимации и 2D-боевые ассеты. Расширять и доводить вертикальный срез: Worlds → выбор героя → убежище → движение/обыск → инвентарь/карта → одна встреча → бой → результат/возврат. Сначала с локальным адаптером того же API-контракта, затем с HTTP-адаптером к реализации Клода. Не представлять процедурные примитивы и концепт-фоны как финальную 3D-графику.
