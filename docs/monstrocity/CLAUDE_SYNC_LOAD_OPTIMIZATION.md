# Claude: снизить нагрузку Monstrocity, не меняя клиент

Работай только в be-core. Не ослабляй авторитетность энергии, движения, боя и смерти. Клиент уже перестал создавать пустые input-кадры во время бездействия и делать пустой sync перед каждой командой.

## Уже реализовано в клиенте
- Idle / открытая карта / инвентарь: пустой heartbeat раз в min(5000 ms, disconnectAfterSeconds * 400 ms).
- Движение: min(1000 ms, (maxBatchFrames - 1) * inputTickMs, 40% disconnect timeout); inputTickMs не меняется, пакеты содержат последовательные кадры без дыр.
- Бой: около 500 ms (или больший syncIntervalMs в config), с ограничением 40% disconnect timeout. Команды броска/меча отправляются сразу; пустого sync перед ними нет.
- Один запрос на сессию одновременно, очередь команд сохранена. Время до следующего heartbeat считается от начала запроса, а не от его завершения: медленный ответ не добавляет лишнюю паузу.
- В фоне sync не отправляется, остаётся существующий disconnect/resume.

При старом config 50/250/10/5 это снижает idle с ~240 до ~30 запросов/мин, движение до ~133/мин, бой до ~120/мин. Значения оценочные, без сетевых задержек и игровых команд.

## Серверная часть следующего шага
1. Установи совместимую транспортную конфигурацию: inputTickMs=50, maxBatchFrames=40, disconnectAfterSeconds=15. syncIntervalMs можно оставить 250: клиент сам выбирает адаптивный интервал. Это даст idle ~12 запросов/мин, движение ~60/мин. Обновление должно корректно применяться и к существующим активным забегам, не только к новым.
2. Проверь отсутствие захардкоженного лимита 10 кадров. Сервер должен обрабатывать последовательные кадры по фиксированному inputTickMs, не растягивая перемещение на весь интервал между запросами. Пустой пакет означает отсутствие движения, но НЕ остановку времени/энергии/боя.
3. Увеличение disconnect timeout не должно давать дополнительное бесплатное время: граница офлайна остаётся lastSeenAt согласно protocol.md. Grace period выхода вне убежища остаётся отдельной настройкой.
4. Команды pause/unpause/search/consume/throw/sword должны сами выполнять settlement. Не требуй пустого sync непосредственно перед командой. Сохрани revision/idempotency и фиксацию settlement при отклонённой команде.
5. Замерь SQL и время транзакции для пустого sync. Убери повторное чтение/перезапись неизменившегося инвентаря и всего каталога на каждом heartbeat. Не заменяй долговечное состояние глобальной RAM-переменной, не теряй данные при рестарте/нескольких инстансах. Не добавляй платные сервисы без согласования.
6. Не включай rate limit ниже согласованной частоты движений/боя; 429 должен иметь Retry-After и стабильный код ошибки, не generic exception.

Тесты: 60 секунд idle с heartbeat 5s без разрыва; расходы энергии продолжаются; пауза останавливает только предусмотренные часы; 20 кадров/сек в пакетах раз в 1s дают ту же скорость; задержанный пакет не ускоряет героя; пустой пакет после движения останавливает героя; конец поиска/снаряда корректно виден через следующий snapshot; повтор команд не удваивает награды; перезапуск процесса сохраняет состояние.

Сообщи версию config, фактические лимиты для существующих run и замеры нагрузки до/после. Клиентские изменения пока требуют публикации отдельно.
