# Claude: Sort backend
Работай только в be-core. Клиент уже находится в /games/sort, вход Sort Lab в Neon World. Сейчас он явно сохраняет прогресс только на устройстве. Не считай локальные победы серверными наградами.

Реализуй авторитетную одиночную Water Sort. Колба ёмкостью 4, массив цветов хранится снизу вверх. Можно перелить только верхний непрерывный блок одного цвета в пустую колбу или на тот же цвет, максимально до заполнения. Нельзя переливать в себя, из пустой или в полную. Победа: каждая колба пуста либо полна одним цветом. Эталон клиентских правил: src/app/features/games/sort/sort-engine.ts. Уровни должны иметь подтверждённое решение; не используй случайную перестановку без решателя. Локальный генератор — прототип, серверный каталог версионируется.

API с существующей Bearer авторизацией:
GET /api/sort/bootstrap -> {config:{version,capacity:4},progress:{level,bestMoves},run:null|Run}
POST /api/sort/runs {configVersion} -> Snapshot
POST /api/sort/runs/{id}/pour {expectedRevision,from,to} -> Snapshot
POST /api/sort/runs/{id}/undo {expectedRevision} -> Snapshot
POST /api/sort/runs/{id}/restart {expectedRevision} -> Snapshot
Run={id,revision,level,status:'playing'|'won',board:number[][],moves,canUndo}; Snapshot={run,progress:{level,bestMoves}}.
Все POST принимают Idempotency-Key. Повтор ключа возвращает исходный ответ, несовпадающее тело — 409. Revision conflict: 409 {code:'REVISION_CONFLICT',snapshot}; недопустимое переливание: 422 {code:'INVALID_POUR',snapshot}. Проверяй владение забегом. Все команды и переходы уровня атомарны; undo после победы не разрешён. Награды пока не вводи без согласованной экономики. Следующий create после won выдаёт следующий уровень, активный забег возвращается при bootstrap. Restart восстанавливает исходную раскладку; undo отменяет последний ход и уменьшает moves.

Добавь Sort в каталог игр Neon World, launchRoute=/games/sort. Существующие ID мира и маршруты не меняй.

Тесты: запрещённые ходы, частичное переливание, сохранение числа слоёв каждого цвета, победа, undo/restart, повтор запроса, конфликт revision, чужой run, reconnect, решаемость всех уровней. Передай Codex пример bootstrap и команды для подключения HTTP-адаптера. Клиент сейчас не вызывает этот API: подключение выполнять после подтверждения контракта и доступности backend, без молчаливого переноса локальных наград.

## Уточнения контракта
- `progress.level`: следующий незавершённый уровень, начинается с 1. `bestMoves`: объект `{[level:string]:number}` с лучшим количеством ходов по завершённым уровням. При победе `run.level` остаётся прежним, `progress.level` увеличивается ровно один раз.
- Один активный run на пользователя. Повтор create при активном run возвращает его, а не теряет прогресс. После won create создаёт следующий уровень. Restart после won отклоняется, чтобы исключить неоднозначность прогресса.
- `config.version` — строка, версия правил и каталога; неизвестная версия при create возвращает 409 CONFIG_CHANGED, клиент повторно получает bootstrap. Существующие run сохраняют свою исходную версию раскладки.
- `revision` — неотрицательное целое, увеличивается после успешной мутации ровно на один; invalid pour не меняет ни revision, ни историю. Undo разрешён только при canUndo=true и playing. Restart очищает историю и moves.
- Идентификаторы цветов — целые 0..5, каждая колба содержит 0..4 слоя. Для каждого присутствующего цвета ровно 4 слоя. Начни с четырёх цветов, постепенно увеличивай число до шести; стартовые уровни должны быть простыми. В классическом режиме таймер и штраф за размышления не нужны; для timed mode смотри расширение ниже.
- Ответы GET/POST возвращают актуальное полное состояние. При сетевом повторе клиент использует тот же Idempotency-Key; новый пользовательский ход — новый ключ. Не отправляй внутренние ошибки БД клиенту.
- Предоставь OpenAPI и примеры запросов/ответов, включая ошибку с snapshot. Добавь тесты авторизации и транзакций. Не меняй frontend: передай описание выполненной реализации и команды локального запуска отдельно.

## Расширение: режим на время, рекорды и общий рейтинг
Клиент добавил тренировочный спринт на 120 секунд: максимум завершённых уровней, время идёт при сворачивании и просмотре вкладок. Классический прогресс отделён от спринта. Личные рекорды сейчас локальные: минимум ходов для каждого классического уровня и максимум уровней за спринт. Перезагрузка завершает локальную попытку; она не является подтверждённым серверным результатом.

Реализуй authoritative timed mode:
- config содержит timed.durationSeconds=120 и версию общего каталога спринта. Create принимает mode:'classic'|'timed'; классический active run и timed session не должны перезаписывать друг друга.
- Timed snapshot содержит sessionId, startedAt, expiresAt, serverTime, solvedLevels, status:ready|active|expired, текущий Run. Время и успешное решение проверяет сервер. Подмена elapsed/score с клиента невозможна.
- Следующий уровень спринта не сбрасывает expiresAt. Undo и restart текущей раскладки не сбрасывают время и не дают повторного зачёта уже решённого уровня. Переходы идемпотентны, завершение сессии/обновление рекорда/рейтинга атомарны. При запросе после deadline финализируй результат, даже если клиент не вызвал finish.
- GET bootstrap возвращает личные server records classicBestMoves по уровням и timedBestLevels, активные сессии; reconnect восстанавливает оставшееся серверное время. Клиент после подключения больше не считает localStorage источником рейтинга.
- Подключи GET /api/games/sort/leaderboard?limit=50 к существующему Leaderboard DTO (src/app/core/models/leaderboard.model.ts). Клиент уже использует общий компонент LeaderboardComponent с gameId=sort.
- Недельный рейтинг BEST_RUN: score=максимум завершённых уровней в ОДНОЙ подтверждённой 120-секундной сессии. Никаких сумм повторных локальных попыток; детерминированный tie-break: меньше подтверждённых ходов, затем более раннее достижение. Не включай классические результаты в этот рейтинг. Все игроки рейтинга используют одинаковую версию сложности/времени. При смене правил явно разделяй период/сегмент.
- Не вводи награды без согласования. Тесты: граница expiresAt, фон/повторный вход, повтор победной команды, replay старого уровня, чужая сессия, невозможность продлить время undo/restart, повтор финализации, сохранение классического прогресса, сортировка рейтинга и ties.
Передай точный дополненный OpenAPI Codex для подключения команд timed mode; пока клиент показывает, что локальные результаты не отправляются в общий рейтинг.

## UX обновление 27 ноября
Следующий классический уровень открывается автоматически после короткого эффекта победы. Кнопки Start/Next level внутри поля отсутствуют. Клиент допускает одновременно анимирующиеся переливания только для непересекающихся пар колб; занятые source/target заблокированы до завершения их анимации. Не вводи глобальный серверный cooldown на визуальное переливание. При подключении HTTP клиент будет сериализовать команды с актуальным expectedRevision независимо от параллельных визуальных эффектов, а конфликт разрешать авторитетным snapshot. Анимация не является доказательством зачёта; победа/рекорд остаются авторитетными.
